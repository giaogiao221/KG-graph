# 补充约束层说明

本包的补充约束层来自历史 `rawarrange` 资源，但它不是第二套强制 Schema。当前抽取主线的
59 列契约、属性本体、质量门控和 v106 LLM 审核仍然是主机制；补充层仅提供可解释的辅助信号。

## 导入内容与行为

| 资源 | 转换后的文件 | 运行行为 |
|---|---|---|
| `parameter_alias.tsv` | `src/config/supplementary_property_aliases.tsv` | 仅精确别名命中时规范属性名 |
| `predicate_en2zh.tsv`、`schema_extended.json` 的旧关系语义 | `src/config/supplementary_relation_mapping.tsv` | 仅精确旧谓词命中时规范为当前关系类型 |
| `subject_stoplist_explosives.txt` | `src/config/supplementary_subject_denylist.txt` | 精确主语命中时转入候选复核，不删除 |
| `gazetteer.tsv` | `src/config/supplementary_subject_lexicon.tsv` | 只记录词表命中，绝不要求主语必须在词表中 |

## 明确没有导入为硬规则的内容

- 历史 JSON Schema：字段定义与当前 59 列契约不一致，不能覆盖当前导出契约。
- 历史实体/关系全集：不能作为封闭词表，否则会误伤新书、新材料和跨领域术语。
- 黑名单的“直接丢弃”语义：当前版本统一改为人工复核，保留原始证据和事实行。

## 运行位置与审计

- v105：`<v105输出>/<书名>/step_graph_guard/supplementary_constraints_audit.jsonl`
- v106：`<v106输出>/<书名>/step_llm_v106/supplementary_constraints_audit.jsonl`

每条审计记录包含阶段、动作、原值、规范值或命中原因。需要调整策略时，编辑
`src/config/supplementary_constraint_policy.json`；如关闭某个分层能力，将相应
`*_enabled` 字段设为 `false`，然后从头运行该书的对应输出目录。
